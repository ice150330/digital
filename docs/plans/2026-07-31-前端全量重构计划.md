# 前端全量重构计划

> 日期：2026-07-31  
> 依据：[`pen/ui.pen`](pen/ui.pen) 设计令牌样张 + 组件库 + 十路由整页样张  
> 配套文档：[DESIGN.md](../DESIGN.md)、[AGENTS.md](../AGENTS.md)、[docs/plans/Design Tokens.md](Design%20Tokens.md)  
> 原则：**样式统一、交互顺滑、内容简洁、Agent 体验优先**。

---

## 1. 目标

当前前端已实现十路由与核心功能，但存在以下问题：

- 样式仍沿用旧 Element Plus 默认色板，与 `Design Tokens v1.0` 和 `pen/ui.pen` 不一致。
- 图标使用 `@element-plus/icons-vue`，风格单一、辨识度不够。
- Agent 页体验偏技术化：无历史会话列表、无流式打字效果、图表与工具轨迹混在一起、工具监控不够直观。
- 部分页面组件零散，空态/错态/加载态不够统一。
- 交互细节粗糙：hover 反馈弱、表单校验提示不统一、页面转场生硬。

本计划目标：

1. **全面对齐 `pen/ui.pen` 视觉样张**：颜色、字体、间距、圆角、阴影、组件状态。
2. **接入 `Unicons` 图标集**：通过 `@iconify/vue` 统一图标，替换 Element Plus 图标。
3. **重构 Agent 分析台**：历史会话、流式输出、图表输出、工具调用监控四块体验全面提升。
4. **统一交互与内容**：让系统更像「可答辩的数据分析产品」，而不是「技术演示页」。

## 3. 范围

**在范围内：**

- `frontend/src/` 下全部样式、组件、页面、路由、API 调用。
- 新增/改造组件：按钮、表单、卡片、表格、图表、导航、消息、空错态、Agent 消息、工具监控等。
- Agent 历史会话、流式输出、图表内联、工具调用可视化。
- 图标全局替换为 `Unicons`。

**不在范围内：**

- 后端算法与模型改造（除非 Agent 流式输出需要新增接口）。
- 新增业务路由或数据分析维度。
- P2 功能：暗色全站主题、移动端适配、复杂权限。

---

## 4. 重构原则

1. **先改令牌，再改组件，最后改页面**：不要直接硬编码颜色。
2. **视觉真相唯一来源**：`pen/ui.pen` 与 [Design Tokens.md](Design%20Tokens.md) 为准，[DESIGN.md](../DESIGN.md) §6 为落地解释。
3. **图标统一**：所有图标走 `@iconify/vue`，图标集用 `Unicons`（默认线形 `uil`，可按需换实心 `uis` 或单色 `uim`）。
4. **Agent 优先**：Agent 页作为答辩核心演示路径，投入最多交互细节。
5. **内容口语化**：算法描述用大白话，不要堆砌英文术语；必须出现的英文只保留标识符、API 路径、技术包名。
6. **渐进式实施**：分阶段合并，每阶段保证 `npm run build` 通过、页面能打开。

```bash
cd frontend
npm install @iconify/vue
```

`@iconify/vue` 按需加载图标，无需把 `Unicons` 整包打入；使用示例：

```vue
<script setup>
import { Icon } from '@iconify/vue'
</script>

<template>
  <Icon icon="uil:home" />
</template>
```

**说明：** `uil` 是 Unicons Line（线形），`uis` 是 Unicons Solid（实心），`uim` 是 Unicons Monochrome（单色）。默认统一用 `uil`，需要强调状态时可局部换 `uis`。

#### 6.5.3 状态管理设计

本次重构引入 **Pinia** 管理跨页面状态（之前 CHANGE.md 已说明阶段 6 未引入 Pinia，是因为折叠态无需共享；本次 Agent 历史会话与 runtime 状态需要共享，故引入）。

**Store 划分：**

1. `stores/app.ts`：全局应用状态
   - `health: HealthData | null`
   - `defaultRunId: string | null`
   - `sidebarCollapsed: boolean`
   - `runtime: string`
   - actions：`loadHealth()`、`setRuntime(runtime)`、`toggleSidebar()`

2. `stores/agent.ts`：Agent 会话状态
   - `currentSessionId: string | null`
   - `messages: AgentMessage[]`
   - `sessions: SessionSummary[]`
   - `loading: boolean`
   - `streaming: boolean`
   - `error: string | null`
   - actions：
     - `loadSessions()`
     - `loadSession(id)`
     - `createSession()`
     - `sendMessage(text)`
     - `streamMessage(text)`
     - `retryTool(toolCall)`
     - `deleteSession(id)`

3. `stores/metrics.ts`：模型指标缓存
   - `leaderboard: RunMetrics[] | null`
   - `defaultMetrics: RunMetrics | null`
   - actions：`loadLeaderboard()`、`loadRunMetrics(runId)`

**原则：**

- Store 只做状态聚合与 API 调用转发，不做复杂计算。
- 组件通过 `storeToRefs` 读取，通过 actions 修改。
- 刷新页面后状态可重新加载，不依赖本地持久化（会话列表除外，可缓存最近 50 条摘要）。

#### 6.5.4 可复用逻辑（composables）

| `useHealth.ts` | 轮询 /health，返回健康状态 |
| `useSession.ts` | 管理当前会话 ID、加载历史消息 |
| `useStreamChat.ts` | 封装打字机/真实流式消费 |
| `useToolSummary.ts` | 把 tool_trace 条目生成中文摘要与图标 |

### 6.7 Agent 页重点改造

这是本次重构的核心。目标：让 Agent 页看起来像「真正的分析助手」，而不是「API 调试页」。

#### 6.7.1 数据结构与状态模型

**消息类型：**

```typescript
interface AgentMessage {
  id: string              // 前端生成的消息 ID，用于 key 与滚动定位
  role: 'user' | 'assistant'
  content: string         // 纯文本内容（已消毒，禁止 HTML）
  streaming?: boolean     // 是否正在流式输出
  streamingText?: string  // 流式过程中已显示的部分文本
  parts?: MessagePart[]   // 富媒体块：文本、图表、工具时间线、五段契约
  runtime?: string        // pi / local / template
  piFallback?: boolean    // 是否发生降级
  latencyMs?: number
  createdAt: string
}

type MessagePart =
  | { type: 'text'; content: string }
  | { type: 'chart'; spec: ChartSpec }
  | { type: 'toolTimeline'; trace: ToolTraceItem[] }
  | { type: 'facts'; items: string[]; title: string }
  | { type: 'inferences'; items: string[]; title: string }
  | { type: 'recommendations'; items: string[]; title: string }
  | { type: 'openQuestions'; items: string[]; title: string }
```

**会话摘要：**

```typescript
interface SessionSummary {
  sessionId: string
  lastUserMessage: string
  updatedAt: string
  runtime: string
  toolCount: number
  messageCount: number
}
```

**会话生命周期：**

```text
新建会话 → 用户输入 → 前端 optimistic 显示用户消息 → 调用 chat/stream →
  创建/更新 assistant 消息 → 流式填充文本 → 工具时间线逐步展开 →
  图表内联渲染 → 五段契约淡入 → 会话列表刷新
```

#### 6.7.2 历史会话

**功能：**

- 左侧新增「会话列表」边栏，宽度 240px，展示最近 30 条会话。
- 每条会话显示：
  - 最后一条用户问题（单行截断）
  - 时间（相对时间，如「3 分钟前」）
  - runtime 标签
  - 工具数/消息数
  - 会话 ID 前 8 位
- 点击会话即可加载完整历史，包括用户问题、助手回复、工具轨迹、图表。
- 支持「新建会话」按钮清空当前会话。
- 会话列表支持按关键词搜索（搜用户问题内容）。
- 支持删除会话（前端软删除，可选调用后端 `DELETE`）。
- 当前会话高亮显示。

**实现：**

- 优先复用 `fetchAuditRecent` 获取历史会话列表（已有 `session_id` + `user_message`）。
- 若后端新增 `GET /agent/sessions`，则切到该接口。
- 点击后调用 `fetchAgentSession(session_id)` 加载完整会话数据。
- 使用 `stores/agent.ts` 管理当前会话与历史列表。
- 会话列表本地缓存最近 30 条，避免每次进页面都请求。

#### 6.7.3 流式输出

**功能：**

- 发送问题后，助手回复逐字/逐句显示，而不是等整段返回后一次性展示。
- 流式过程中显示「正在思考…」脉冲动画。
- 流式过程中可看到工具调用状态：「正在查询模型指标…」「正在绘制图表…」。
- 流式结束后，五段契约（观察事实、推断、建议、待澄清）逐块淡入。
- 流式过程中允许「停止生成」按钮（仅真实流式）。
- 流式失败时，已生成的文本保留，并显示错误提示与重试按钮。

**实现方案：**

- **方案 A（真实流式）：** 后端新增 `POST /agent/chat/stream` SSE 接口，前端用 `fetch + ReadableStream` 消费。
  - 事件类型：
    - `text`：文本片段，追加到 assistant 消息
    - `tool_start`：开始调用工具，在时间线新增「执行中」步骤
    - `tool_end`：工具返回结果，更新步骤状态与耗时
    - `chart`：图表 spec，追加 chart 块
    - `facts/inferences/recommendations/open_questions`：五段契约片段
    - `done`：流式结束
    - `error`：流式出错，保留已生成内容并标记错误
  - 需要后端改造，体验最佳。
- **方案 B（前端模拟）：** 先调用现有 `POST /agent/chat`，拿到完整回复后在前端用打字机效果逐字展示。
  - 无需后端改造，可快速上线。
  - 工具状态可在收到完整响应后按时间顺序动画展示，模拟实时感。

**建议：**

- 第一阶段用方案 B 快速上线流式视觉体验。
- 第二阶段再用方案 A 做真实流式，提升工具监控实时性。
- 两种方案共享同一套 `AgentMessage` 数据结构，方便切换。

#### 6.7.4 图表输出

**现状：** 已有 `render_chart` 工具 + `ChartCard` 组件。

**增强：**

- `ChartCard.vue` 支持 6 种图表类型：bar、line、pie、scatter、heatmap、funnel。
- 图表在消息流中以「卡片」形式出现，带标题、口径、免责声明脚注。
- 图表支持点击放大：弹窗或抽屉展示，弹窗内可切换数据视图（如柱状/表格）。
- 图表支持「重新生成」按钮：用户可要求 Agent 用不同方式重画。

- 未知 chart_type 时展示友好兜底：「暂不支持该图表类型，已为您保留数据」。

### 7.2 建议后端新增接口

为支持真实流式与更好的历史会话体验，建议后端补充：

1. `GET /agent/sessions`：返回会话摘要列表（替代从审计日志反推）。
   - 字段：`session_id`、`last_user_message`、`created_at`、`updated_at`、`runtime`、`tool_count`、`message_count`。
   - 排序：按 `updated_at` 倒序，默认 30 条。
2. `POST /agent/chat/stream`：SSE 流式对话。
   - 请求体与 `POST /agent/chat` 相同：`message`、`session_id`、`runtime`。
   - SSE 事件：
     - `text`：`{ delta: string }`
     - `tool_start`：`{ tool: string, args?: object }`
     - `tool_end`：`{ tool: string, ok: boolean, result?: object, error?: string, duration_ms: number }`
     - `chart`：`{ spec: ChartSpec }`
     - `facts/inferences/recommendations/open_questions`：`{ items: string[] }`
     - `done`：`{ session_id: string, latency_ms: number }`
     - `error`：`{ code: string, message: string }`
3. `DELETE /agent/sessions/{session_id}`：软删除会话（可选，P1）。

**优先级：**

- P0：普通对话 + 历史会话回放（已有接口，前端改造即可）。
- P1：真实流式接口（提升体验，需要后端配合）。

   - 保留现有 `getData` / `postData`。
   - 新增 `postStream(path, body, onEvent)`：封装 SSE / ReadableStream 消费。
   - 新增统一错误码解析：`VALIDATION_ERROR`、`MODEL_NOT_LOADED`、`AGENT_TOOL_FAILED`、`PI_NOT_INSTALLED`、`LLM_UNAVAILABLE` 等，映射为中文提示。
2. `api/agent.ts`：
   - 新增 `fetchSessions()`、`deleteSession(id)`、`chatAgentStream(body, handlers)`。
   - `chatAgentStream` 返回 `abort` 函数，支持停止生成。
3. 全局 loading/error 状态：
   - 普通请求由页面级组件管理 loading。
   - Agent 流式请求由 `stores/agent.ts` 管理 `streaming` 状态与 `error`。

### 7.4 数据缓存策略

- 模型指标列表（`/models/metrics`）进入页面时加载，手动刷新才更新。
- 大屏各板块独立请求，失败只影响对应板块。
- Agent 会话列表进入 Agent 页时加载，发送新消息后刷新。
- 不整页缓存预测结果，保证每次查询都是最新。

## 10. 性能与体验优化

### 10.1 包体积

- `@iconify/vue` 按需加载，不整包打包图标。
- ECharts 继续按需注册（`utils/echarts.ts`）。

- 阶段 4 结束后检查 `npm run build` 产物体积，若过大再考虑分包。

### 10.2 渲染性能

- `BaseChart.vue` 继续使用 ResizeObserver，容器级监听，unmount 时 dispose。
- Agent 消息列表使用虚拟滚动（若单会话消息超过 50 条）。
- 工具时间线默认折叠参数/结果，避免一次性渲染大 JSON。
- 图表弹窗内使用懒加载，不打开时不渲染内部 ECharts。

### 10.3 体验细节

- 输入框支持 `Ctrl+Enter` 发送，`Shift+Enter` 换行。
- 发送按钮在 loading/streaming 时禁用或变为停止按钮。
- 表单校验失败时，自动滚动到首个错误字段。
- 所有操作超过 300ms 显示 loading 或骨架屏。
- 错误提示提供「重试」或「查看详情」入口。

## 14. 风险与回退

| 风险 | 影响 | 应对 |
|------|------|------|
| 一次性改动太大，构建失败 | 高 | 分阶段合并，每阶段 `npm run build` 通过 |
| 新图标包与旧图标尺寸不一致，导致布局错乱 | 中 | `Icon.vue` 统一尺寸，阶段 1 全仓替换并检查 |
| 样式令牌重写后，旧页面代码大量报错 | 中 | 保留旧变量别名过渡，不一次性删除 |
| Agent 流式需要后端接口，后端时间不足 | 中 | 第一阶段用前端模拟打字机，接口后补 |
| 大屏重构改动大，答辩前不稳定 | 高 | 大屏放在阶段 1 或阶段 2 早期完成，留出测试时间 |
| 过度追求动画影响演示流畅度 | 中 | 动画可配置，`prefers-reduced-motion` 关闭，演示前可一键简化 |
| Pinia 引入增加学习成本 | 低 | 仅用于跨组件状态，文档清晰、示例简单 |
